# Правила Codex для разработки на 1С:Предприятие.Элемент

Этот документ фиксирует рабочие правила для Codex при генерации и правке кода `1С:Элемент` (`.xbsl`) и YAML-описаний элементов проекта. Правила собраны по локальной документации из `docs/help/ru` и нормализованному языковому корпусу `ai-docs-lang/out`.

## Базовые установки

- Генерировать код и YAML в русскоязычном стиле. Английские ключевые слова в языке поддерживаются, но для этого проекта Codex должен использовать русские ключевые слова: `метод`, `пер`, `знч`, `если`, `иначе`, `выбор`, `когда`, `для`, `из`, `пока`, `возврат`, `новый`, `это`, `как`, `не`, `и`, `или`.
- Ключевые слова языка пишутся в нижнем регистре. Имена типов, методов, переменных, полей и элементов проекта пишутся в `UpperCamelCase`, если локальный файл не задает иной стиль.
- Константы писать `БОЛЬШИМИ_БУКВАМИ_С_ПОДЧЕРКИВАНИЯМИ`.
- Типы исключений называть с префиксом `Исключение`.
- Для перечислений предпочитать имена со словом `Вид`, а не `Тип`.
- Отступ в `.xbsl` и YAML: 4 пробела, без табуляции.
- Ориентир длины строки: 120 символов. Длинные выражения переносить с операцией в начале перенесенной строки, кроме конкатенации строк, где `+` допустим в конце строки.
- Не ставить `;` после каждой простой инструкции. Символ `;` закрывает составные инструкции и объявления: `метод`, `структура`, `перечисление`, `если`, `выбор`, `для`, `пока`, `попытка`, `область`.

## Типизация и `Неопределено`

- Язык статически типизирован. Автоматического приведения типов в обычных выражениях нет. Для реального преобразования использовать конструкторы или методы, для сужения составного/базового типа использовать `как`.
- `Объект` является базовым типом для всех типов, кроме `Неопределено`. Для произвольного значения использовать `Объект?`, а не `Объект`.
- `неизвестно` отключает проверки типов на этапе компиляции и должен применяться только там, где это действительно нужно. У `неизвестно` нет значения типа `Тип` и нет собственного значения.
- `Null` использовать только для работы с базой данных и результатами запросов. Для обычного пустого значения использовать `Неопределено`.
- Тип `Неопределено` в списках типов явно не писать. Использовать сокращение `?`.
- Для двух типов писать `Строка?`, а не `Строка|?`.
- Для трех и более типов писать `Строка|Число|?`, а не `Строка|Число?`.
- В составных типах рядом с `|` пробелы не ставить: `Строка|Число|?`.
- Если переменная объявлена без инициализации, ее тип должен иметь значение по умолчанию или включать `Неопределено`. Иначе будет ошибка инициализации.
- Если составной тип не включает `?`, всегда задавать инициализацию: `пер Значение: Строка|Число = 0`.
- Если тип включает `?` или указан `неизвестно`, значение без инициализации будет `Неопределено`.

## Главное правило для YAML-типов

- В YAML у свойств, реквизитов, полей структур и параметров с ссылочным типом без явного значения по умолчанию обязательно делать тип допускающим `Неопределено`.
- Для одного ссылочного типа писать `Тип: Клиенты.Ссылка?`.
- Для нескольких ссылочных типов писать `Тип: ПриходнаяНакладная.Ссылка|РасходнаяНакладная.Ссылка|?`.
- Не писать ссылочный тип без `?`, если нет явного `ЗначениеПоУмолчанию` или другого гарантированного начального значения.

```yaml
# Плохо: у ссылочного типа нет значения по умолчанию.
Реквизиты:
    -
        Имя: Клиент
        Тип: Клиенты.Ссылка

# Хорошо.
Реквизиты:
    -
        Имя: Клиент
        Тип: Клиенты.Ссылка?
```

- То же правило применять к полям структур и хранимых структур. Если поле имеет тип собственной структуры, хранимой структуры, ссылочного типа или другого типа без безопасного значения по умолчанию, то либо задать `ЗначениеПоУмолчанию`, либо включить `?`.

```yaml
Поля:
    -
        Имя: Ответственный
        Тип: Пользователи.Ссылка?
    -
        Имя: АдресДоставки
        Тип: АдресДоставки?
```

- Для составных свойств интерфейсных компонентов значение по умолчанию можно не указывать только если у типа есть значение по умолчанию, в частности если тип включает `Неопределено` или `Null`.
- Если значение YAML относится к составному типу и не является очевидным скалярным литералом, указывать тип значения явно через вложенный `Тип`. Это особенно важно для `Объект`, `Массив<Объект>`, коллекций и структурных значений.

```yaml
Поля:
    -
        Имя: Данные
        Тип: Массив<Объект>
        ЗначениеПоУмолчанию:
            -
                Тип: Строка
                Значение: Строка текста
            -
                Тип: Булево
                Значение: Истина
```

## Переменные, константы и параметры

- Использовать модификаторы:
  - `пер` для изменяемой переменной;
  - `знч` для переменной только для чтения;
  - `исп` для потомков `Закрываемое`, которые должны автоматически закрываться при выходе из области видимости;
  - `конст` только на уровне модуля.
- Не объявлять несколько переменных одной инструкцией.
- Не использовать переменную до объявления.
- Не объявлять переменную повторно в одной области видимости.
- Не использовать переменную в собственном выражении инициализации.
- Если тип очевиден из литерала или конструктора, тип переменной обычно не дублировать.
- Значения по умолчанию параметров, констант и аннотаций должны вычисляться во время компиляции: литералы, литералы коллекций, обращения к константам и допустимые операции над ними. Вызовы методов, обращения к свойствам и конструкторы там не использовать.

## Методы

- Метод объявляется через `метод Имя(Параметр: Тип = Значение): ТипВозврата`.
- Если метод ничего не возвращает, тип возврата можно не указывать; если нужна явность, использовать `: ничто`.
- Возврат значения выполнять через `возврат Значение`.
- Параметры передаются по значению: переназначение параметра не меняет переменную вызывающего кода, но изменение состояния переданного экземпляра возможно.
- Для методов с необязательными параметрами перед обязательными использовать именованные аргументы при вызове.
- Если порядок параметров потенциально неочевиден, использовать именованные аргументы.
- `@ИменованныеПараметры` означает, что метод или конструктор нельзя вызывать позиционно.
- Не перегружать методы только типом возвращаемого значения.
- Не создавать перегрузки, где составной тип пересекается с типом другой перегрузки.
- Не использовать `Объект` как тип перегруженного параметра, если есть более конкретные перегрузки.

## Структуры, перечисления и исключения в `.xbsl`

- Структура объявляется блоком `структура Имя ... ;`.
- Поля структуры объявляются как переменные: `пер Поле: Тип` или `знч Поле: Тип`.
- `обз` помечает обязательное поле конструктора.
- Поле `знч` можно установить только при создании экземпляра.
- Поле структуры не должно иметь тип самой определяемой структуры.
- Если обязательное поле не имеет явного значения инициализации, его тип должен иметь значение по умолчанию.
- Для структуры автоматически создается конструктор по полям в порядке их объявления. Если нужен именованный конструктор, добавить `@ИменованныеПараметры` перед `конструктор`.
- Статические методы структуры объявлять как `статический метод`.
- Перечисление объявляется через `перечисление`, минимум с одним элементом. Значение по умолчанию помечается `умолчание`.
- К элементу перечисления обращаться как `ИмяПеречисления.Элемент`. В `выбор` по значению перечисления допустим краткий элемент без имени перечисления.
- Пользовательские исключения объявлять через `исключение`. Выбрасывать через `выбросить новый Исключение...(Описание = "...")`.

## Операции и проверки

- Равенство и неравенство: `==`, `!=`; присваивание: `=`.
- Булевы операции: `и`, `или`, `не`. Они ленивые.
- Булево значение проверять напрямую: `если Флаг`, `если не Флаг`; не писать `Флаг == Истина` или `Флаг == Ложь`.
- `Неопределено` проверять через `== Неопределено` или `!= Неопределено`; не через `это Неопределено`.
- Для отрицательной проверки типа писать `Значение это не Строка`, а не `не (Значение это Строка)`.
- `?.` использовать для безопасного доступа к значению, которое может быть `Неопределено`. Результат при `Неопределено` тоже `Неопределено`. В левой части присваивания `?.` нельзя.
- `!` использовать только когда логически доказано, что значения `Неопределено` быть не может. Иначе будет исключение времени выполнения.
- `??` использовать для значения по умолчанию при `Неопределено`: `Значение ?? ЗначениеПоУмолчанию`.
- Тернарная операция: `Условие ? ЕслиИстина : ЕслиЛожь`. Оба результата должны быть совместимы с ожидаемым типом.
- `как` не преобразует данные между типами, а приводит значение к одному из допустимых типов. Для преобразования использовать конструктор или метод.

## Инструкции

- `если` принимает только логическое выражение и закрывается `;`.
- `выбор` бывает полной формы `выбор Значение` и предикатной формы `выбор` без выражения. Ветка `когда` может содержать несколько условий через запятую.
- `для Индекс = Начало по Конец [шаг N]` использовать для счетчика. Счетчик объявляется самим циклом и имеет область видимости тела цикла.
- `для Элемент из Коллекция` использовать для обхода коллекций и строк.
- `пока Условие` использовать для цикла с заранее неизвестным числом итераций.
- `прервать` и `продолжить` работают в циклах.
- `попытка`/`поймать`/`вконце` закрывается `;`. В `вконце` не использовать `возврат`, `прервать`, `продолжить`.
- Для закрываемых ресурсов использовать `исп`; закрытие выполняется автоматически в обратном порядке объявления.

## Коллекции

- Предпочитать литералы коллекций ручному наполнению:
  - массив: `[1, 2, 3]`;
  - множество: `{1, 2, 3}`;
  - соответствие: `{"RUB": 1, "BYN": 31.01}`.
- Для типизированных литералов использовать:
  - `<Число>[1, 2]`;
  - `<Число>{1, 2}`;
  - `<Число, Строка>{1: "один"}`;
  - пустые: `<Число>[]`, `<Число>{}`, `<Число, Строка>{:}`.
- Если тип литерала не указан явно, он выводится из целевой переменной или как объединение типов элементов.
- Индексы коллекций в примерах документации начинаются с `0`.

## Строки

- Использовать интерполяцию вместо сложной конкатенации.
- `%Имя` и `%{Выражение}` используют `ВСтроку()`.
- `$Имя`, `${Выражение}` и `${Выражение|Формат}` используют `Представление()`.
- Если при интерполяции выражение равно `Неопределено`, результатом будет пустая строка.
- При конкатенации со строкой `Неопределено` превращается в строку `"undefined"`, поэтому для пользовательских текстов лучше интерполяция или явная подстановка через `??`.
- Экранировать интерполяцию как `\%` и `\$`, если `%` или `$` должны остаться символами строки.
- Управляющие последовательности: `\н`, `\в`, `\т`, `\\`, `\"`, `\%`, `\$`, `\юNNNNN`.

## Пространства имен, импорт и видимость

- Квалифицированные имена разделяются через `::`: `Подсистема::Пакет::Тип`.
- Полное имя: `Поставщик::ИмяПроекта::Подсистема[::Пакет]::ИмяТипа`.
- Стандартное пространство имен: `Стд`.
- В `.xbsl` блок `импорт` должен быть первым блоком модуля.
- В YAML элемента проекта импорт задается свойством `Импорт`.
- Импорт в YAML элемента проекта не распространяется на его модуль. Если пространство имен нужно в модуле, добавить отдельный `импорт` в `.xbsl`.
- Область видимости элементов проекта задается YAML-свойством `ОбластьВидимости`: `ВПодсистеме` по умолчанию, `ВПроекте`, `Глобально`.
- Область видимости языковых конструкций задается аннотациями: `@Локально`, `@ВПодсистеме`, `@ВПроекте`, `@ВТипе`, `@Глобально`.
- Использовать минимально достаточную видимость. Не ставить `Глобально` без необходимости.
- Окружение у проектных типов задается свойством `Окружение`: `КлиентИСервер`, `Клиент`, `Сервер`. Для методов использовать `@НаКлиенте`, `@НаСервере`, `@ДоступноСКлиента`.

## YAML элементов проекта

- YAML-файлы являются служебным описанием свойств элементов проекта. При генерации вручную сохранять структуру, порядок и стиль существующего файла.
- Для новых YAML-полей предпочитать русское `Ид`, но если в конкретном файле используется `Id`, сохранять локальный стиль.
- Базовые свойства большинства элементов: `ВидЭлемента`, `Ид`, `Имя`, `ОбластьВидимости`, `Импорт`.
- `ВидЭлемента` должен точно соответствовать виду элемента: `Справочник`, `Документ`, `Структура`, `ХранимаяСтруктура`, `КомпонентИнтерфейса`, `РегистрСведений`, `РегистрНакопления`, `Перечисление`, `КонтрактТипа` и т. д.
- Списки описывать через `-` с вложенными свойствами на 4 пробела: `Реквизиты`, `Поля`, `Свойства`, `События`, `ТабличныеЧасти`, `Измерения`, `Ресурсы`.
- Значения `Тип` в YAML использовать в той же системе типов, что и `.xbsl`: `Строка`, `Число`, `Булево`, `Дата`, `ДатаВремя`, `Массив<Тип>`, `Соответствие<Ключ, Значение>`, `ИмяСправочника.Ссылка?`, `Подсистема::Тип`.
- Для вычисляемых свойств интерфейса значение начинается с `=` и содержит выражение языка `1С:Элемент`: `Видимость: =Компоненты.МойФлажок.Значение`.
- Методы, используемые в вычисляемых YAML-свойствах извне модуля, должны иметь подходящую видимость, например `@ВПодсистеме` или `@ВПроекте`.
- Для пользовательских свойств компонента:
  - `ЗначениеПоУмолчанию` можно не указывать только если тип имеет значение по умолчанию или включает `Неопределено`/`Null`;
  - `Контекстное: Истина` требует тип, доступный и на клиенте, и на сервере;
  - контекстные серверные методы должны иметь `@Контекстный` и `@НаСервере`.

## Реквизиты и хранение данных

- Реквизит описывает поле таблицы базы данных. Имя реквизита не должно быть ключевым словом языка или зарезервированным словом языка запросов; `ID`/`ИД` запрещены без учета регистра.
- Реквизиты могут иметь составной тип из поддерживаемых типов, но в одном составном типе нельзя одновременно использовать `Дата` и `ДатаВремя`.
- `ЗначениеПоУмолчанию` для реквизитов не поддерживается у реквизитов-коллекций.
- `ПриУдаленииОбъектаПоСсылке` допустимо только для ссылочных типов.
- Реквизит-коллекция имеет тип `Массив<...>` и порождает отдельную таблицу. В основной таблице нельзя обращаться к нему как к вложенной таблице в запросе.
- Табличные части поддерживаются в ссылочных сущностях: `Справочник`, `Документ`, `ПланОбмена`, `ХранилищеНастроек`, `КонтрактСущности`.
- Табличная часть описывается в `ТабличныеЧасти`, должна иметь явно заданные `Реквизиты`, и порождает структурный тип `ИмяЭлемента.ИмяТабличнойЧасти`.
- Для регистров накопления список `Ресурсы` не может быть пустым. Измерения имеют свойства реквизитов, но не должны использовать неограниченные `Строка`, `Байты` и `ДвоичныеДанныеСсылка`.
- В регистре накопления обязательный стандартный реквизит `Регистратор` должен ссылаться на документы-регистраторы и в YAML обычно задается составным ссылочным типом с `|?`.
- В регистрах сведений измерения образуют ключ записи, порядок измерений важен. Для измерений нельзя использовать неограниченные `Строка`, `Байты` и `ДвоичныеДанныеСсылка`.

## Что Codex должен проверять перед ответом

- Нет ли английских ключевых слов в новом `.xbsl`, если файл не написан в английском стиле.
- Все ли блоки и объявления закрыты `;`.
- Все ли переменные с составным типом без `?` имеют инициализацию.
- Все ли ссылочные YAML-типы без явного значения по умолчанию имеют `?` или `|?`.
- Все ли поля структур/хранимых структур без безопасного значения по умолчанию имеют `?` или `ЗначениеПоУмолчанию`.
- Не используется ли `Null` как обычное пустое значение.
- Не проверяется ли `Неопределено` через `это`.
- Не сравниваются ли булевы значения с `Истина`/`Ложь` без необходимости.
