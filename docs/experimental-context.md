# Экспериментальный контекст Codex

## Что поддерживается

В RC добавлен режим Codex, который использует заметки и поиск по истории вместо повторного сжатия всего диалога в одно резюме. Управление находится в **Настройки → Система → Управление контекстом**. По умолчанию плагин не включает эксперимент.

Настройка `features.context_management.experimental_mode` принадлежит app-server. Она хранится в `config.toml` внутри `CODEX_HOME` подтверждённого пользователя IDE: `<configRoot>/users/<userKey>/codex-home`. Это выбор пользователя для его диалогов, не параметр установки плагина, приложения или браузера. Токены авторизации не передаются в webview.

В поставке используется Codex **0.154.0**. Эта версия проверяет совместимость режима с моделью при запуске серверного диалога. Установленный переключатель подтверждает настройку, но не обещает, что любая модель или подписка использует новый механизм.

По документации OpenAI режим требует входа через ChatGPT с Plus, Pro или Pro Lite. Вход по API-ключу, неизвестный тариф или отсутствие входа блокируют включение. Уже включённый режим можно выключить и без подходящего тарифа. Плагин получает тип учётной записи и тариф через `account/read`, а не угадывает их по названию модели.

Источники: [параметры конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference), [изменения Codex](https://learn.chatgpt.com/docs/changelog), [app-server API](https://learn.chatgpt.com/docs/app-server).

## Чтение и изменение

1. При первом открытии «Системы» выполняется проверка. Открытие других разделов не запускает её. Кнопка обновления повторяет проверку.
2. `experimentalFeature/list` проверяет наличие `context_management`; список обрабатывается постранично. `config/read` с `includeLayers: true` возвращает эффективное значение и версию пользовательского слоя.
3. Переключение пишет только один ключ через `config/value/write`, с `mergeStrategy: upsert` и `expectedVersion`. Настройки MCP и другие ключи не перезаписываются. Конфликт версий или переопределение конфигурацией проекта/сервера отображается рядом с переключателем.
4. Активный ответ, очередь в процессе отправки или запрос планировщика документации блокируют смену режима. Во время сохранения новые ответы не запускаются.
5. После успешной записи свободный app-server перезапускается. Настройка повторно считывается; существующие идентификаторы диалогов сохраняются. Это позволяет применить режим к следующему `thread/resume`, не обрывая текущую генерацию.
6. Смена пользователя IDE, остановка runtime или запоздалый ответ аннулируют старое состояние проверки. Webview передаёт `scopeId` и `revision`; они не позволяют сохранить устаревший выбор в другой пользовательский контекст.

`experimentalApi: true` разрешает экспериментальные методы API, но сам по себе не включает режим. Плагин не использует `experimentalFeature/enablement/set` для неподдерживаемого этим методом ключа и не меняет `historyMode` вручную.

## История и смена приложения

Локальная история интерфейса остаётся в `chats.json`. Нативная история и контекст app-server находятся в пользовательском `CODEX_HOME`; плагин не копирует их в Markdown и не подменяет заметками собственного формата.

При смене приложения в рамках того же подтверждённого пользователя, сервера, пространства и имени проекта сохраняется `backendThreadId`. `thread/resume` получает новый `cwd` и `excludeTurns: true`. При переносе сервер должен подтвердить новый каталог. Плагин не повторяет такой запрос без `cwd`, чтобы не продолжить работу в старом приложении.

Таймауты, ошибки MCP и транспортные ошибки не означают, что история отсутствует. Создание замены допустимо только при явном ответе о недоступном сохранённом диалоге. Существующий краткий перенос из локального transcript остаётся аварийным механизмом, а не эквивалентом нативного контекста.

## Проверки

```sh
npm run build
npm run check:experimental-context
npm run check:runtime
npm run check:history
npm run check:protocol
npm run check:chat-shortcuts
```

Модульные тесты проверяют тарифы, постраничную выдачу, сохранение одного ключа, версии конфигурации, ошибки и слой пользователя. Проверки runtime охватывают занятые диалоги, блокировку новых запросов, смену пользователя во время перезапуска, сохранение thread ID и перенос `cwd`. Playwright проверяет переключатель, возврат после ошибки и вёрстку в светлой/тёмной теме на ширинах 320, 390, 900 и 1280 px.

Локальные проверки не подтверждают работу экспериментального механизма на оплаченном диалоге или запуск Windows-бинарников. На целевой Theia нужно войти через подходящую учётную запись ChatGPT, включить режим, продолжить существующий диалог и проверить длинную сессию. Отдельно проверить отключение и повторный вход в IDE.
