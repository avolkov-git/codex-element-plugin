# Просмотр браузера агента

Версия: `1.0.5-rc1`. Ветка: `feature/1.0.5-rc1-browser-viewer`.

## Использование

Включите браузерное тестирование в настройках плагина. Нажмите кнопку монитора в шапке чата или вызовите команду `Codex: Браузер агента`. Плагин откроет отдельную вкладку рядом с текущим редактором. Затем попросите агента открыть приложение через встроенный Playwright MCP.

В списке страниц выберите нужную. Пауза, скрытие и закрытие вкладки прекращают передачу кадров; агент продолжает работу. Клики и ввод в окне просмотра не передаются браузеру. Для управления используйте сообщения агенту.

Просмотр относится к браузеру текущего сеанса IDE, пользователя и проекта. Чаты этого сеанса используют общий управляемый browser runtime. Выбор страницы в просмотре не переключает активную страницу MCP и не переводит фокус в Chromium.

## Передача изображения

```text
Playwright MCP / initPage
  -> CDP Page.startScreencast в существующей странице
  -> локальный Unix socket / Windows named pipe
  -> BrowserViewerService
  -> отдельный WebviewPanel / postMessage
```

Плагин использует штатный `WebviewPanel` и общий HTML-загрузчик с fallback для HTTP-оболочки Element. Новые модули Theia и публичный CDP-порт не нужны. Хук `browserViewerHook.js` входит в `dist` и использует Node.js из browser runtime.

Ограничения потока: JPEG до 1440×900, качество 55, не более пяти кадров в секунду, до 512 КиБ base64 на кадр. На стороне хука хранится один последний кадр; сервис ждёт подтверждения Webview перед следующим. При отсутствии подтверждения в течение трёх секунд сервис приостанавливает трансляцию. Кнопка возобновления запускает её снова.

Кадры не попадают в чат, историю, запросы модели и журналы. Плагин не сохраняет видео. Скриншоты, которые агент отдельно запрашивает через MCP, остаются обычными артефактами браузера.

Для каждого запуска runtime плагин создаёт новый IPC-адрес и случайный токен. Смена пользователя, проекта или приложения, остановка и завершение runtime отключают старый источник и очищают изображение. Подключение наблюдателя не меняет сетевые разрешения и настройки Chromium sandbox.

## Проверка

```sh
npm run build
npm run check:browser-viewer
npm run check:browser-viewer-ui
```

Для проверки штатной HTTP-оболочки задайте `ELEMENT_WEBVIEW_PRE`: путь к `ide/theia/products/browser-app/lib/webview/pre` бандла Element. В CI без бандла можно явно задать `CODEX_TEST_SKIP_ELEMENT_WRAPPER=1`; такая проверка не подтверждает совместимость с оболочкой Element.

Сквозная проверка MCP и кадров:

```sh
node scripts/browser-viewer-smoke.cjs /path/to/browser/platform
```

Скрипт требует runtime платформы, на которой его запускают. Параметры `--development-node` и `--development-browser` разрешают проверку JavaScript MCP с локальными исполняемыми файлами; это не проверка бинарников Windows на macOS.

Перед установкой на Windows Server нужно проверить вкладку в работающей IDE: навигацию агента, несколько страниц, паузу, скрытие вкладки, перезапуск runtime и смену проекта. Локальные тесты не заменяют этот прогон.

Используемые API: [Playwright BrowserContext.newCDPSession](https://playwright.dev/docs/api/class-browsercontext#browser-context-new-cdp-session), [CDP Page.startScreencast](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-startScreencast).
