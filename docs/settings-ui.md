# Настройки Codex для 1С:Элемент

Панель настроек следует утверждённому макету: пять разделов вместо длинной общей формы, компактные строки инструментов и правые панели редактирования. Документ описывает реализованный интерфейс и его поведение. React-чат и оформление чата не меняются.

## Архитектура и разделы

[SettingsPanelManager](../src/settingsPanelManager.ts) создаёт отдельный webview в серверной Theia IDE и передаёт `settings.snapshot` и события операций. Интерфейс использует [settings.js](../media/settings.js) и [settings.css](../media/settings.css), без React-renderer настроек. Подписи и пояснения русские; имена, пути и данные внешних инструментов сохраняют исходный вид.

Иконки локальные: [генератор](../scripts/build-settings-icons.js) превращает Lucide в статические SVG размером 18 px со штрихом 1.75; [settings-icons.js](../media/settings-icons.js) загружается перед интерфейсом, без CDN и runtime-импорта Lucide. Знак Codex берётся из `resources/icons/codex.svg`, лицензия Lucide лежит в `media/settings-icons.NOTICES.txt`.

| Раздел | Содержимое |
| --- | --- |
| Подключение | Прокси, логин и пароль; отдельное сохранение. |
| Документация | Каталог нормализованной документации, нормализация и открытие базового контекста. |
| Инструменты | Встроенный браузер, его проверка и параметры запуска; пользовательские MCP-серверы. |
| Навыки | Поиск, фильтры источника и состояния, переключатели; подробности раскрываются в строке. |
| Система | Экспериментальный контекст, сводка версий компонентов и настройка/установка ripgrep в правой панели. |

Браузер и управление MCP находятся только в «Инструментах». Список MCP исключает `managed === "browser"`: встроенный сервер не дублируется. Адрес приложения IDE показан текстом только для чтения; ручных полей URL приложения и `allowedOrigins`/`allow-origins` нет. Сохранение браузера отправляет только `enabled` и `disableSandbox`. Поле URL пользовательского HTTP MCP остаётся редактируемым.

- Шрифт и базовый размер из IDE: `--vscode-font-family`, `--vscode-font-size` (fallback 14 px); интерлиньяж 1.5, `letter-spacing: 0`. Заголовки 24/16/14 px, пояснения преимущественно 12/13 px. Моноширинный текст наследует `--vscode-editor-font-family`.
- Шапка 56 px; сетка `205px minmax(0, 1fr)`. Основная область прокручивается отдельно, имеет `scrollbar-gutter: stable`, отступы `32px 36px 44px`; контент до 900 px, формы до 640 px. Секции и строки разделены линиями, без вложенных карточек.
- Скругления: поля и кнопки 5 px, навигация 6 px, метки 3 px. Кнопки от 34 px, поля от 36 px; обычные иконки 18 px. `:focus-visible` даёт обводку 2 px с отступом 3 px и цветом `--vscode-focusBorder` (fallback `--link`).
- Правая modal drawer имеет ширину `min(400px, 100%)`, начинается ниже шапки; тело прокручивается отдельно от кнопок внизу. Подложка `#00000015`, тень `-10px 0 30px #0000000e`.

| Ширина webview | Адаптация |
| --- | --- |
| До 800 px включительно | Навигация 175 px; отступы основной области `28px 24px 36px`. |
| До 580 px включительно | Навигация сверху с переносом кнопок, footer скрыт; формы и пары данных в одну колонку; действия в строках переносятся. Drawer на всю ширину; основные кнопки от 38 px; h1 22 px, отступы контента `24px 18px 32px`. |
| До 360 px включительно | Уменьшаются шапка и её текст; боковые отступы контента 14 px. |

Переключатели используют переходы 120 ms, индикатор ожидания вращается за 900 ms. `prefers-reduced-motion` отключает анимации и переходы; `forced-colors` добавляет системные границы и цвета контролов.

## Поведение и данные

- Начальная страница: «Инструменты», если нет допустимого сохранённого `activePage`. Панель записывает в webview persistence только `activePage`, сохраняя существующие сторонние ключи. Черновики, пароль, фильтры, позиции прокрутки и состояние drawer живут в памяти, не восстанавливаются после пересоздания webview. Перерисовка сохраняет фокус, выделение ввода и прокрутку; во время IME-композиции откладывается.
- Drawer блокирует основную область через `inert`/`aria-hidden`, использует `role="dialog"`, `aria-modal` и удерживает Tab-фокус внутри. Escape, крестик и подложка закрывают панель с сохранением черновика в памяти; кнопка «Отмена» сбрасывает соответствующий черновик. После закрытия фокус возвращается к вызвавшему действию; закрытие блокируется на время сохранения.
- Ошибки операций имеют свой scope и появляются у соответствующего действия либо в footer редактора; проблемный раздел отмечается в навигации. Технические подробности MCP и проверки браузера находятся в свёрнутом `<details>`. Повторные проверки/сохранения блокируются на время соответствующей операции; частичные списки интеграций сохраняют доступные данные.
- Базовый контекст: общий bundled-файл `resources/context/codex-element-language-rules.md` в каталоге установки плагина, не правила отдельного проекта. [BaseContextService](../src/baseContextService.ts) читает и сохраняет его через редактор IDE, проверяет revision против конфликтующих правок и ограничивает размер 96 KiB UTF-8. Путь из webview не выбирает файл.
- «Перечитать» доступно и при `dirty`, кроме времени сохранения. Для несохранённых изменений панель показывает inline-подтверждение «Перечитать файл и отменить несохранённые изменения?» с кнопками «Перечитать файл» / «Оставить черновик». «Оставить черновик» отменяет перечитывание; эта отмена и ошибка чтения сохраняют текст, `dirty` и прежнюю `revision`. Только успешное подтверждённое чтение заменяет текст и `revision` и сбрасывает `dirty`. Сообщение о конфликте больше не ведёт к кнопке, заблокированной из-за черновика; общая «Отмена» в drawer по-прежнему сбрасывает правки.
- Версия плагина приходит из `package.json`, версия Codex app-server обозначает поставку из `bin/runtime-manifest.json`, а не измерение запущенного процесса. [BrowserRuntimeService](../src/browserRuntimeService.ts) берёт версии браузерных компонентов из manifest. При отсутствии значений таблица показывает «Нет данных»; краткие версии Chromium/MCP также видны у браузера и в его drawer. Статусы берутся из snapshot и результатов операций: «Компоненты установлены» не означает успешный запуск или доступность приложения IDE.

## Проверки

Экспериментальный контекст оформлен обычной строкой с переключателем и отдельной проверкой доступности. Ошибка остаётся в этой секции, отмечая «Систему» в навигации. Проверка запускается только при открытии раздела или явном обновлении; сохранение подтверждается app-server. Активные ответы не прерываются. Подробности протокола, подписок и хранения: [экспериментальный контекст](experimental-context.md).

Команды из `package.json`, запускать из корня плагина. `build` обновляет сборочные артефакты.

```sh
npm run check:browser-runtime
npm run check:settings-browser
npm run check:experimental-context
npm run check
npm run build
```

`check:browser-runtime` включает тесты браузера, приложения IDE, панели и базового контекста. [UI-проверка](../scripts/settings-browser-check.cjs) использует реальные локальные ассеты с тестовыми snapshot: 1280x900, 1024x820, 390x844 в светлой теме и 900x900 в тёмной. Она проверяет размещение, drawer, фокус, persistence, фильтры и ошибки; снимки пишет в `CODEX_TEST_ARTIFACTS` либо временный каталог. По умолчанию нужен Chrome; `CODEX_TEST_BROWSER_CHANNEL=bundled` выбирает Chromium Playwright. Версии и статусы из fixture не описывают реальный runtime.

При переносе 9 сентября 2026 года прошли 59 тестов `check:browser-runtime`, четыре сценария размеров окна, включая тёмную тему, а также `npm run check` и `npm run build`. UI-тест выполняет HTML из [webviewHtml](../src/webviewHtml.ts) под его CSP в трёх режимах: штатные ресурсы, отказ всех внешних ресурсов и отказ только файла иконок. В двух последних случаях проверяется резервная встроенная загрузка. Отдельно прошли проверки запуска расширения, сервисов и комплектности поставки; сценарии панели и базового контекста также проверены на Node.js 22.13.1.

Эти проверки не заменяют запуск в серверной Theia на Windows. После переноса поставки следует пройти [чеклист RC](1.0.0-rc-testing.md). В узком окне список MCP расположен ниже браузера и может потребовать прокрутки.
